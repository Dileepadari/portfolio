# Comment style

One convention, so a single documentation generator can read the whole
codebase. This file describes what is already in the tree; it is not a wish
list.

## Formats

| Language | Format | Generator |
|---|---|---|
| TypeScript, TSX | TSDoc `/** */` with `@param`, `@returns`, `@throws` | TypeDoc |
| JavaScript (`scripts/*.mjs`) | JSDoc `/** */` | TypeDoc |
| SQL (`supabase/migrations/*.sql`) | `-- Purpose:` above each object | manual |

## Rules

- Every module starts with a docblock saying what it is for and, where the
  choice is not obvious, why it exists at all.
- Every exported function, component, hook and route handler gets a docblock.
  A one-line private helper does not need one.
- Short. A summary line, then parameters, return and errors. Under six lines
  is the target.
- Say what and why, never how. If the body already says it, do not repeat it.
- An inline comment earns its place only by explaining something the code
  cannot: a workaround, an ordering requirement, where a magic number came
  from, a bug in a dependency. Comments that narrate a statement are deleted
  on sight, as are commented-out code and changelog notes.
- Do not restate a parameter's name as its description. Say what the value
  must be or where it comes from.

## Tags

Used consistently so comments can be aggregated across repositories:

- `@module <area>` on every module. The areas in this repository are `app`,
  `admin`, `auth`, `blog`, `contact`, `data`, `profile`, `projects`,
  `theming`, `ui` and `docs`.
- `@public` on anything that is part of an external surface, which here means
  the admin gateway's HTTP routes.
- `@since` is not used: this project has no released versions to reference.

## What is excluded

- `src/components/ui/**` is vendored shadcn/ui. It is upstream code, kept close
  to upstream so it can be updated, and is not annotated.
- `src/integrations/supabase/types.ts` is generated by `supabase gen types`.
  Anything written into it is lost the next time it is regenerated.
- `supabase/seed.sql` is generated by `scripts/build-seed.mjs` from the hosted
  database.
